# Agent Task Loop: Godot Development Workflow

This document defines the strict, iterative execution framework for AI agents and developers implementing features, bug fixes, or refactoring tasks in **Godot Engine** projects.

---

## Task Execution Loop

Every assigned task must strictly adhere to the following 5-phase loop:

```
[1. Plan & Branch] ➔ [2. Implement] ➔ [3. Validate & Test] ➔ [4. Review & Refine] ➔ [5. Commit & Merge]
```

---

## Phase 1: Planning & Version Control Setup

1. **Task Context & Analysis**:
   - Review task requirements, target Godot scene(s), script(s), and resource files.
   - Verify dependencies (e.g., signals, autoloads, custom resources, scene hierarchy).

2. **Branch Creation**:
   - Ensure the main repository is clean (`git status`).
   - Create and checkout a dedicated feature/fix branch:
	 ```bash
	 git checkout main
	 git pull origin main
	 git checkout -b feature/<task-name>  # or fix/<task-name>
	 ```

---

## Phase 2: Implementation (Godot Specific)

1. **Modify / Create Assets**:
   - **Scripts (`.gd`)**: Keep logic modular, typed (`var x: int`), and signal-driven. Avoid hardcoded node paths; use `@onready @export var` references.
   - **Scenes (`.tscn`)**: Ensure proper node hierarchy and node naming conventions.
   - **Resources (`.tres`)**: Keep data decoupled from UI and game logic.

2. **Godot Code Standards**:
   - Use static typing everywhere possible (`func update_health(amount: float) -> void:`).
   - Clean up unused node references, signals, and warnings in the editor/console.
   - Respect project folder structure (e.g., `res://scenes/`, `res://scripts/`, `res://assets/`).

---

## Phase 3: Real Validation & Testing

Do **not** consider code finished until validated through real engine runtime/tests.

1. **Automated Unit / Integration Tests** *(if configured, e.g., GUT plugin)*:
   - Run tests command-line or via Godot runner:
	 ```bash
	 godot --headless -s addons/gut/gut_cmdln.gd
	 ```

2. **Manual Engine Validation**:
   - Launch scene independently to verify local behavior:
	 ```bash
	 godot res://path/to/scene.tscn
	 ```
   - Check Debug Console for:
	 - Zero errors or orphan nodes (`Orphan String Names` or leaked `RefCounted` objects).
	 - No script runtime errors/warnings.

3. **Regression Check**:
   - Run main project scene to ensure no breaking changes in global state or autoloads:
	 ```bash
	 godot
	 ```

---

## Phase 4: Self-Review & Refactoring

1. **Diff Audit**:
   - Review exact changes made to ensure no temporary debug prints or unintended `.import` file changes were added:
	 ```bash
	 git diff
	 ```

2. **Asset Integrity**:
   - Ensure `.import` files generated by Godot are committed if they belong to newly added raw assets.
   - Ensure external dependencies and sub-scenes resolve correctly without broken resource paths.

---

## Phase 5: Commit & Integration

1. **Stage & Commit**:
   - Stage relevant files (do **not** include local user settings like `.godot/` folder):
	 ```bash
	 git add <modified_files>
	 git commit -m "<type>(<scope>): concise task description"
	 ```
   - *Commit type examples*: `feat`, `fix`, `refactor`, `chore`.

2. **Merge / Push**:
   - Push feature branch or merge back to main:
	 ```bash
	 git checkout main
	 git merge --no-ff feature/<task-name>
	 git branch -d feature/<task-name>
	 ```

---

## Loop Guardrails & Rules

- **No Premature Done**: Never mark a task complete without running the modified scene and checking for console warnings/errors.
- **Isolate Changes**: Do not modify unrelated `.tscn` files or global settings unless explicitly required by the task.
- **Clean Git State**: Always confirm `.gitignore` includes Godot cache (`.godot/`).
